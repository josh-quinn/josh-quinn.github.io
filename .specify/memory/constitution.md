# personal-site Constitution

This repository is a public GitHub Pages site and the testbed for a small AI-engineering toolkit. These rules are non-negotiable. A change that breaks one is rejected, however good the rest is. The `gate` tool enforces them with hooks and CI.

## I. Tests come first, from the spec

- Acceptance tests derive from the acceptance criteria in `specs/<feature>/spec.md`.
- They are written by the `test-author` role (see `agents/src/test-author.md`), which reads the spec only.
- They are committed failing, before any implementation, with the commit trailer `Gate-Test-Author: <task-id>`.
- The TDD workflow (test list, red-green-refactor, cold-context verify) is the pinned `spec-kit-tdd` extension; see `docs/decisions/0002-spec-kit-tdd.md`. It is referenced here, not restated.

## II. The implementer never edits acceptance tests

- The `implementer` role must not create, edit, move or delete anything under `tests/acceptance/**` or `.gate/**`.
- If an acceptance test is wrong, the implementer stops and reports it. The test author changes it, in a separate commit.

## III. Privacy: nothing private in the repo or the built site

- No phone number, date of birth, passport or ENG1 details, street address or email address appears in the repo (source, tests, fixtures, docs, commit messages, PR text, history) or in any built HTML.
- Location is no finer than "Ireland".
- The only contact routes are the LinkedIn and GitHub profile links.
- Committed CV content stays fictional (a placeholder persona) until the owner approves real content. Real data lives only in the gitignored `.private/` folder.
- CV PDFs are never committed.
- Privacy tests and scanner rules use patterns, never literal private values. Fake personal data in tests is assembled at runtime.
- Committed docs use `~`, never an absolute home path.

## IV. Design rules

- No CSS framework, no Tailwind, no component kit.
- Colour, font and spacing come only from token custom properties defined from `DESIGN.md`.
- No client-side JavaScript on CV pages (`/cv/` and everything under it), and none on any page except the one exception below.
- **Scoped exception, home-page terminal only** (owner decision, 2026-11-24; `docs/decisions/0008-home-terminal-js.md`): the home page (`/`) may ship one first-party module script, for the terminal, and nothing else may ship JavaScript. The script has no dependencies, makes no network calls, and never uses `eval` or `innerHTML` with input. The terminal has a CSS or static fallback that works without JS, and is accessible (a labelled input, `aria-live` output, no keyboard trap). Every other page stays JS-free. A smoke test enforces it.
- No third-party brand marks, logos or names in the repo.

## V. Tooling and process

- Adopt proven tools before building. Record the decision as an ADR in `docs/decisions/`; ADRs are binding.
- No tool may need a third-party API key. AI evals run locally only; CI holds no AI tokens.
- Everything has a Claude Code route and a Copilot CLI route. The role subagents are defined once in `agents/src/` and generated by `npm run agents:sync`; never edit the generated files.
- Tool configuration lives under `~/.config/jq-tools/<tool>/`, never in the repo.
- Commits are conventional. One task is one pull request.

## VI. Definition of done

A task is done when `gate task <id>` passes and the owner merges the pull request. Nothing is auto-merged.
